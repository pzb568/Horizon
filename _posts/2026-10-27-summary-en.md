### [Preprint Claims Exponential Time Hypothesis Disproved](https://github.com/openai/math/blob/main/preprints/The-Exponential-Time-Hypothesis-is-False-October-25-2026/paper.pdf) ⭐️ 8.0/10

A preprint posted on GitHub on October 25, 2026 by author vok claims to have disproved the Exponential Time Hypothesis \(ETH\), a central conjecture in complexity theory that asserts certain problems, such as SAT, require essentially 2^\{Ω\(n\)\} time. The paper provides a theoretical algorithm that allegedly runs in sub‑exponential time for ETH‑related problems, but explicitly states it does not imply sub‑exponential algorithms for all NP problems under standard polynomial‑time reductions. The claim is currently unverified and has not undergone peer review.

hackernews · vok · Oct 26, 21:59 · [Discussion](https://news.ycombinator.com/item?id=50251661)

**「Exponential Time Hypothesis \(ETH\) Overview」** The Exponential Time Hypothesis is a conjecture in computational complexity that asserts 3‑SAT cannot be solved in sub‑exponential time; formally, there exists a constant c&gt;1 such that any algorithm for n‑variable 3‑CNF formulas requires time at least c^n. ETH underlies many fine‑grained lower‑bound results for problems like SAT, graph algorithms, and, recently, analyses of self‑attention in neural networks.

**「Impact」** If the proof holds, it would reshape expectations for worst‑case SAT solving and could invalidate existing lower‑bound arguments for self‑attention, potentially opening research into sub‑quadratic transformer implementations, though practical algorithms may still be far from usable.

**「Community Discussion」** Commenters noted that the result does not automatically give sub‑exponential algorithms for general NP problems \(cochne\) and questioned whether the techniques could be applied to real‑world SAT solvers \(criemen\). Others speculated about implications for transformer efficiency, asking if self‑attention could become sub‑quadratic if the proof is correct \(strommec\).

### [Microsoft adds Python‑specific Type Server Protocol \(TSP\)](https://github.com/microsoft/pylance-release/blob/main/docs/tsp/type-server-protocol.md) ⭐️ 7.0/10

Microsoft has published a new Type Server Protocol \(TSP\) that is dedicated to Python type‑query operations. The protocol is defined in the Pylance release documentation and is intended for developers of language‑server and other Python tooling. It does not replace the Language Server Protocol but adds a Python‑focused RPC layer for type information. The announcement is a technical addition rather than a broad industry shift.

hackernews · adamnemecek · Oct 26, 18:14 · [Discussion](https://news.ycombinator.com/item?id=50248371)

**「Prerequisite concepts」** The Type Server Protocol \(TSP\) is a JSON‑RPC‑based interface that lets clients query a Python type‑analysis server for information such as symbol definitions and type inference. It is designed for use with Microsoft’s Pylance Python language server, extending the generic Language Server Protocol model to expose Python‑specific type data to external tooling.

**「Impact」** Tooling developers can implement TSP to obtain more direct type‑query capabilities, potentially improving performance or feature granularity for Python language servers. However, early feedback shows mixed adoption: basedpyright’s maintainer has criticized the protocol, while the Ruff type checker is considering support, indicating that compatibility decisions will need to be made on a per‑tool basis.

**「Community Discussion」** Commenters note that basedpyright’s maintainer has publicly criticized TSP, whereas the Ruff project’s discussion suggests it may adopt the protocol. Others question why a separate Python‑only protocol is needed when the generic LSP already exists, highlighting uncertainty about its practical benefits.
